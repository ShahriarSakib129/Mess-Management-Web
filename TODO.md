# MessMate delivery checklist

- [ ] Secure app login uses unique Mess ID/username and password, hashed credentials, logout, friendly errors, rate limiting, secure session cookies, CSRF protection, and no public self-registration; first admin creation requires a one-time environment/CLI bootstrap and never uses a hardcoded production password.
- [ ] Backend authorization distinguishes Super Admin/Mess Admin, Current Mill Manager, and Regular Mess Member; role checks protect every sensitive page and endpoint, and members cannot edit other members, official payment records, meal rates, manager assignments, approvals, or admin operations.
- [ ] Admin can create, edit, suspend, reactivate, and archive members; assign roles and Mess IDs; set joining/leaving dates, opening balances, and dues; review activity and audit logs; and import/export authorized records where supported.
- [ ] Monthly manager assignments have period dates, prevent overlapping assignments, expire automatically, preserve historical attribution, allow advance appointment, and never transfer admin permissions.
- [ ] Manager can enter breakfast, lunch, dinner, decimal, guest, off, and special meals; edit with reasons and audit history; see missing/unconfirmed entries; submit correction workflows; enter/search bazar records with item/category/quantity/unit price/total/date/vendor/notes/payer/receipt; and approve/reject/correct expenses with duplicate protection.
- [ ] Manager cashbook records opening cash, member receipts, bazar/other spending, reimbursements, returns, calculated balance, daily reconciliation, discrepancies, and admin review; handover summarizes meals, costs, deposits, reimbursements, cash, issues, unpaid balances, and outgoing/incoming managers.
- [ ] Members have personal dashboard, statement, meal history, approved bazar records, payment history, reports, notifications, current rate/manager, previous months, balances, and correction requests, with no direct official-record edits.
- [ ] Accounting uses NUMERIC/Decimal and a single documented BDT sign convention: approved meal-related expenses divided by eligible meal quantities yields the meal rate; member cost includes meal cost, configured common allocation, and approved charges; net balance includes opening credit, verified deposits, refunds, and valid debits; zero meals never produce infinity/NaN; locked historical statements preserve rates and changes are auditable.
- [ ] Payments support deposits, advances, partial payments, cash, bank, bKash, Nagad/configurable methods, references, dates, receiver, pending/verified states, refunds, openings, dues, credit carry-forward, duplicate prevention, reversal history, and no false gateway claims.
- [ ] Accounting periods are separately identifiable, switchable, historically queryable, closable/reopenable with audit logs, and expose meals, food/common expenses, income/deposits, dues, rates, member costs/balances, carry-forward, manager, and handover.
- [ ] In-app announcements/notifications support unread/read states for rates, bazar summaries, deadlines, missing meals, expense decisions, manager changes, and closure.
- [ ] UI is premium, accessible, responsive on mobile/tablet/desktop, mobile-first for meal/bazar entry, uses BDT and Bangladeshi dates, supports responsive tables/cards, loading/empty/error states, and avoids horizontal overflow.
- [ ] Normalized schema includes users, roles/assignments, settings, periods, managers, meals, corrections, categories, expenses/receipts, deposits, payments, refunds, adjustments, statements, closings, cashbook, announcements, notifications, audit logs, login sessions, constraints, indexes, timestamps, and transactional financial updates.
- [ ] Deployment includes requirements, Gunicorn/Procfile or Docker/Render config, `.gitignore`, `.env.example`, `/health`, `/manus-routes.json`, Supabase/Render documentation, migration/bootstrap flow, no production fake data, and tests for auth, permissions, manager rotation, corrections, approvals, calculations, balances, closing/reopening, history, duplicate payments, unauthorized access, and database errors.
